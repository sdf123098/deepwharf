# DeepWharf 会话与实施记录

> 本文档存档了从"评审桌面化计划"到"发布 DeepWharf"的完整对话与工程决策。
> 项目：DeepSeek Harness（`dsh`）的 Windows 桌面封装。最终命名 **DeepWharf**。
> 仓库：https://github.com/sdf123098/deepwharf

---

## 0. 起点：计划评审

用户给出《DeepSeek Harness Desktop 桌面化实施计划》（40 节），问"是否过于复杂"。

**结论**：架构正确且是可行方案里最简单的（Electron + 独立 Node + spawn `dsh web` + HTTP 探测 + 进程树清理），
但文档把小事包装成大工程。真正的复杂度不在计划写的地方，而在被低估的地方：
`dsh web` 的运行时行为、包体积、Defender 对大量小文件的实时扫描。

建议：砍流程、先做最小垂直切片、先验证 `dsh web` 运行时行为。

## 1. 项目调研（deepseek-ai/deepseek-harness）

- 一切皆插件（Cordis 框架）；默认 Web UI 在 `127.0.0.1:3080`；`npx @deepseek-ai/dsh web` 启动。
- Node 要求 `^22.19 || >=24`；`DSH_HOME` 为官方原生环境变量（默认 `~/.dsh`）。
- `dsh web --port N`（参数在 `web` 之后）；端口被占直接 EADDRINUSE 退出。
- 首次启动自动初始化 profile（离线，从安装目录建 junction，不联网）。
- `dsh plugin --profile web add <pkg>` **硬依赖 PATH 里有 pnpm**（转发给 pnpm）。
- 带 native 二进制：`node-pty`（winpty/OpenConsole）、`@vscode/ripgrep-win32-x64/rg.exe`（均预编译，离线可用）。
- 网络：`registry.npmjs.org` 与 `github.com` 在本机不通；`registry.npmmirror.com` / `nodejs.org` 通。
  → 所有更新/搜索/下载默认走 npmmirror。

## 2. MVP（Phase 1-9）实现与验证

目录 `src/main/`：`index.ts`（编排）、`harness-process.ts`（spawn+探测+清理）、`port.ts`、
`paths.ts`、`log.ts`、`window.ts`、`i18n.ts`、`settings.ts`、`harness-update.ts`、`plugin-store.ts`、
preload（shell/plugin/settings）。

- 单实例锁、端口自动分配、HTTP ready 探测（无固定延时）、退出 `taskkill /T /F` 清进程树。
- `DSH_HOME` 指向 `%APPDATA%\<产品名>\harness`；日志 `desktop.log`/`harness.log`。
- 内置 Node（`resources/runtime/node.exe`）+ 内置 Harness（vendor npx 缓存）+ 内置 npm/pnpm。
- electron-builder 产出 NSIS + Portable；`extraResources` 放 ASAR 外。
  - **坑**：electron-builder `createFilter` 无条件排除 `from` 根下的 `node_modules` → 改为指向更深一层 / 后改为单压缩包。
- 修复 bug：`currentHarnessVersion` 需 `dirname(dirname(bin.js))`。

## 3. 图标 / 本地化 / 主题 / 界面

- 图标：从 `@deepseek-ai/dsh-web-frontend/dist/favicon.svg` 提取官方鲸鱼标志，
  `scripts/make-icon.mjs`（sharp + png-to-ico）生成 `build/icon.ico`（蓝底 #4D6BFE + 白鲸，16~256）。
  - 坑：sharp 多页 ICO 输出损坏 → 改用 `png-to-ico`。
- 本地化：`i18n.ts` zh-CN/en-US，`app.getLocale()`/设置覆盖；覆盖菜单、对话框、启动页、商店、设置。
- 主题：外壳默认跟随系统（`prefers-color-scheme` + `nativeTheme`），标题栏 overlay 颜色同步，可手动覆盖
  （映射 `nativeTheme.themeSource`）。修复了"浅色系统却是深色顶栏"的割裂。
- 界面：主窗口无边框 + 自绘合并标题栏（logo + 商店/设置 + 原生窗口按钮），`<webview>` 嵌入 Harness；
  商店/设置窗口 `setMenu(null)` 去菜单栏；设置窗口含语言/主题/自动更新/DevTools/版本与更新（更新收进版本区）/日志。

## 4. 插件商店

- 数据源：npm registry 搜索 `dsh-plugin`（npmmirror），即官方插件生态的可安装集合。
- 安装：内置 pnpm → `dsh plugin --profile web add <pkg>`（官方机制，自动写 cordis 配置），装完提示重启。
- 实测：搜索返回 20 条；`dsh-plugin-greeter` 安装成功写入 profile package.json。

## 5. Harness 自动更新

- 启动/菜单检查 `registry.npmmirror.com/@deepseek-ai/dsh/latest`；新版用内置 npm 装到临时目录，
  原子替换 `resources/harness/node_modules`，重启。仅打包版生效。
- 外壳自更新：`SHELL_UPDATE_URL` 指向 `{version}` JSON 才比对（未配置提示当前版本）；electron-updater 留作后续。

## 7. 关键坑位备忘

- Git Bash 里 `&` 后台 + `$!` 拿到的是 MSYS PID，`taskkill` 杀不到真实 node 进程（测试脚本孤儿来源）。
- `cmd` 批处理里 `%~dp0..\node.exe` 的 `..` 引号解析坏 → 用 `for %%I in ("%~dp0..") do set RUNTIME_DIR=%%~fI` 规范化。
- pnpm.cmd shim 需 `SETLOCAL` + 规范化路径写法。
- electron-builder `extraResources` 根下 `node_modules` 被过滤。
- sharp 不能读 ICO、多页 ICO 输出坏；用 png-to-ico 写、sharp 只栅格化 SVG。
- 安装慢主因 Defender 逐文件扫描；对策：裁剪文件数 + 单压缩包 + （未来）代码签名。

## 9. 启动小框修复（2026-08-17）

**现象**：每次打开应用，主窗口中央出现一个无标题、按钮无文字的小框 + 半透明暗罩。

- 根因：外壳页替代 `window.prompt` 的模态 `#dwPrompt`（`main-shell.html`）用 `hidden` 属性隐藏，
  但作者样式 `.dwPrompt { display:flex }` 压过 UA 的 `[hidden] { display:none }` 规则（作者样式
  优先级高于 UA 样式，与选择器特异性无关）→ 弹窗自页面加载即常驻；两个动作按钮从未设置文案，
  渲染成两个无色块。`hidden=true` 的关闭操作同样被该规则顶掉，弹窗视觉上无法关闭。
- 修复：
  - `main-shell.html` / `settings.html` CSS 增加 `[hidden] { display:none !important; }`
    （设置页 `.row { display:flex }` 同样压过 hidden，远程控制端口/令牌等行因此常显）；
  - `main-shell.js` I18N 增加 `cancel`/`ok`（取消/确定、Cancel/OK），启动时填入按钮文案。
- 同类排查：`remote.html` 的 `.card`/`.err`、`plugin-store.html` 的 `.progress` 均未设 display，
  log-viewer/onboarding 未使用 hidden 属性 → 安全。**教训：给带 hidden 属性的元素写 display
  规则之前，先加 `[hidden]` 保护行。**
- 验证：Electron `capturePage` 无头截图——修复前与用户截图完全一致，修复后初始界面干净、
  正常触发弹窗时标题与按钮齐全；`npm test` 47/47 通过。
